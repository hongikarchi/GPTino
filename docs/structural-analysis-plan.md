# GPTino 구조해석 도입 계획 (라이브러리 구축 + 검증)

**작성일**: 2026-07-30 · **상태**: 계획 (미실행) · **근거**: Karamba 사용모드 워크플로 리서치
(10 에이전트, 공식 문서 + API 레퍼런스 + GitHub + McNeel 포럼 교차 검증) + 3-렌즈 적대 검토
(구조공학 정확성 / GPTino 아키텍처 적합성 / 검증 엄밀성 — 블로커 3·메이저 10·마이너 4 반영).

---

## 배경 & 확정 결정

- **엔진 전략**: Karamba3D를 기준선(baseline)으로 먼저 구축, 오픈소스 대안(PyNite 우선)은
  라이선스 걸림돌 시점(서버 배포·무라이선스 사용자층)에 착수. Karamba가 대안의 정확도 잣대.
- **모드 선택**: GH 컴포넌트 배선이 아닌 **C# 스크립트 컴포넌트 안 Toolkit 코드** (하이브리드).
  근거: 데이터트리/노드 tolerance 에러 회피, fingerprint 충돌 표면적 감소, 예외 기반 에러로
  반박 게이트 친화, 반복 루프(최적화) 표현 가능. 시각화는 네이티브 뷰 컴포넌트 유지(브로커 시각화).
- **라이선스 사실**: 세션 스코프 — 사용자의 Rhino 세션 라이선스를 스크립트 코드도 그대로 사용.
  무라이선스 = 트라이얼 캡(**요소** 기준 보 20 / 쉘 50, 비상업). **부재 분할 요소도 캡에
  카운트**되므로 벤치마크 모델은 분할 수까지 포함해 캡 내로 역산 설계.
- **판정 산술 주체**: LLM이 아닌 결정론적 코드. GPTino는 코드 생성·오케스트레이션과
  수치의 자연어 해석만 담당 (거짓성공 반박 원칙의 연장).

## 파이프라인 (6계층 — 하중조합·판정 분리가 핵심)

```
[1] 모델 입력    Rhino 참조 기하 + GH 파라미터
                → 구조 기하 변환 (중심선 추출, 노드 일치/교차 해결, mm→m)
                + 지지조건 + 원시 하중(고정 G / 활하중 Q 구분 태깅) + 단면/재료 배정
[2] 하중조합     ULS (계수하중: γG=1.35·γQ=1.5, ψ 조합계수) ↔ SLS (특성/준영구, 비계수)
                — 활용률·강도 체크는 ULS 결과로, 처짐 판정은 SLS 결과로. 혼용 금지.
[3] 솔버 해석    Karamba C# 스크립트 (Toolkit). 기본 = 1차 해석(AnalyzeThI).
                전체 구조 좌굴 고유치·고유모드도 이 계층의 해석 종류 (후순위).
[4] 원시 출력    변위 / 부재력 / 반력 (+ 좌굴 하중계수, 고유진동수)
[5] 판정 계층    활용률·설계 체크·단면 최적화 = 결정론적 코드.
                Karamba 경로: 내장 Utilization·OptiCroSec 호출 — 재구현 금지.
                처짐 한계 등 내장이 없는 판정: 사전 제작·버전 고정 판정 스크립트
                (bake_manager.py 방식, 아래 "판정 코드 실체")가 수행. 잡마다 새로 짜는
                스크립트는 "검증된 코드 경로"가 아님.
[6] 해석·피드백  GPTino가 [4][5]의 수치를 읽어 자연어 피드백 + 반박 게이트 판정.
```

- **좌굴의 이중 소속**: (a) 전체 구조 좌굴 고유치 해석("몇 배 하중에서 불안정해지나")은
  [3] 솔버 해석이며 후순위; (b) **부재 설계식 내 좌굴 감소계수 χ는 [5]의 일부이고
  Karamba Utilization(EC3 체크)에 포함되어 M3 초기 범위에서 즉시 등장**. 따라서
  **좌굴길이 정책이 M3 선결 과제**: 하나의 물리 부재가 여러 요소로 분할된 경우 요소
  길이 기준 기본값은 비보수(위험측) — 물리 부재 단위로 좌굴길이를 지정하는 규칙을
  판정 스크립트에 내장하고, 분할 기둥 검증 케이스 1건 이상을 게이트에 포함.
- Karamba 3.1.x 제약: 좌굴 고유치·비선형은 Toolkit 파사드 밖(version-unstable 정적 클래스)
  → 초기 범위는 1차 해석 + 활용률 + 단면 최적화까지. 하중조합은 Toolkit에 존재
  (`FactoryLoad.LoadCaseCombination`) — M1에서 실지원 범위 확인.

## 스킬 설계 (2개 + 판정 스크립트, 상시 비용 = 인덱스 3줄)

| 스킬 | 내용 |
|---|---|
| `gh-karamba-cookbook.md` | 코드 생성 관용구: Toolkit 진입(`new KarambaCommon.Toolkit()` + `MessageLogger`), **단수** `UnitsConversionFactory.Conv()`, Analyze류 out 파라미터 **`out var` 필수**, `FromGH`/`ToGH` 변환, `GH_Model` 래핑, mm→m 단위 규칙, `#r` 참조 규칙(버전 pin — 아래 리스크), MessageLogger/out-string 에러 판독, K3D_tests 패턴만 신뢰(공식 가이드 절반은 구버전 코드). **솔버 스크립트 전용 실행 규칙**: 기하·지지·하중이 전부 와이어 입력이므로 방어 기본값 단독 실행이 불가 → 입력 미배선 시 solve를 건너뛰고 상태 출력(`model=null`, `solved=false`)으로 표시, 배선 완료 후의 최종 execute만 유효. 그린 판정은 `solved=true` 출력 어서션과 결합(null-guard 스킵이 "해석 안 돌고 초록"이 되는 공동화 방지). |
| `structural-analysis.md` | 도메인 지식: 6계층 파이프라인과 계층 책임, 지지조건 상식(고정/핀/롤러), 하중 상식(자중·등분포·집중 + **G/Q 태깅**), **ULS/SLS 하중조합 구분**(활용률=ULS, 처짐=SLS), 어떤 해석을 언제(1차/좌굴/고유모드), 결과 해석 기준 — **적용 조건 병기**: 처짐 한계 L/250(총처짐/외관)·L/300(취성 마감 손상)은 단순 지지 스팬의 SLS 관례이며 캔틸레버는 환산(L=2×내민길이) 또는 한계 강화 적용, 활용률 임계 1.0과 여유율 관례, **판정 산술은 코드에 위임** 원칙, 트라이얼 캡(분할 포함) 인지 |

## 판정 코드 실체 (M3 산출물)

- `assets/skills/structural_check.py` (bake_manager.py 방식의 사전 제작·버전 고정 페이로드):
  SLS 처짐 한계 비교(스팬 정의·캔틸레버 환산 포함), 좌굴길이 규칙, V4 대조용 자체
  활용률 계산(대안 경로 대비). GPTino는 이 스크립트를 배선/실행할 뿐 수정하지 않음.

## 라이브러리 구축 계획 (단면·재료 데이터)

**용도**: (a) PyNite 등 대안 경로의 필수 입력 (b) GPTino의 요약·신뢰도 라벨
(c) 교차검증 기준값. Karamba 경로 자체는 동봉 테이블을 쓰므로 즉시 의존성은 아님.

**스키마** (`assets/data/structural/` — SI 고정(m 기반), 값마다 출처·유효 자릿수 필드):

- `sections.json`: family(IPE/HEA/…), name, 치수(h, b, tw, tf, **r 필릿 반경**), A,
  **Av,y/Av,z(전단면적)**, Iy, Iz, **iy/iz(회전반경 — 수록값, 파생 규칙 i=√(I/A) 병기)**,
  J, **Iw(뒤틀림상수 — LTB 체크용)**, Wel,y, **Wpl,y**, Wel,z, **Wpl,z**, 단위질량.
- `materials.json`: name, E, G, 밀도, 강도(fy/fu 또는 fc/fm), 재료측 부분안전계수 γM, 출처.
- 하중측 계수(γG/γQ/ψ)는 재료 데이터가 아니라 판정 스크립트의 상수 테이블에 소속.

**배포·접근 메커니즘** (현재 실체 없음 — M4 산출물로 신설):

1. `GPTino.AgentHost.csproj`에 `assets\data\**` Content ItemGroup 추가 (skills/instructions와
   동일 패턴) — 이것 없이는 빌드/publish/Yak 스테이징에 포함되지 않음.
2. 접근 통로: **`data_read` 툴 신설** (skill_read와 별도 — skills/ 폴더에 json을 넣으면
   파일마다 스킬 인덱스 줄이 늘어 "상시 2줄" 설계가 깨짐).
3. Rhino 프로세스 안 스크립트 컴포넌트는 AgentHost 경로를 모름 → 판정 스크립트에는
   **필요한 행만 페이로드로 주입** (전체 파일 경로 의존 금지).

**단계**:

1. **Phase 1 (벤치마크 최소)**: IPE 80–600 전열 + HEA/HEB 대표 치수, S235/S355.
   출처 우선순위: 표준 규격 원본 > Karamba 동봉 테이블 > 2차 카탈로그.
2. **Phase 2 (실무 폭)**: RHS/SHS/CHS 강관, 콘크리트 C20/25–C50/60, 집성재 GL24h 등.
3. **Phase 3 (국내 실무)**: KS D 3502 H형강 열, SS275/SM355 — 한국 사용자 대응.

## 검증 계획 (5층)

| 층 | 내용 | 합격 기준 |
|---|---|---|
| **V1 데이터** | 구축값 vs Karamba 동봉 테이블 vs 공개 카탈로그 3-way 대조 스크립트 + 자기일관성 체크(대상 수식 명시 열거: Wel=I/c, i=√(I/A) — 필릿 기여 때문에 치수→A·I 재계산은 제외) | **필드별 차등**: A·I·W ≤ 1%, **J ≤ 5%**(근사식 차이가 통상적) |
| **V2 이론해** | 손계산 정답 문제 세트 — Karamba 결과와 비교. **조건 명시**: 세장 부재(L/h ≥ 20)로 전단변형 영향 통제(Karamba 보요소는 전단변형 포함, 이론해는 Euler-Bernoulli). 캔틸레버 끝처짐 `PL³/3EI`, 단순보 등분포 `5wL⁴/384EI`(**≥10분할** — 등가절점하중 보간 때문), 축력 부재, 오일러 좌굴 `π²EI/L²`(핀-핀 Le=L 명기, **부재당 ≥4분할**, 후순위) | 오차 ≤ 1% |
| **V2.5 모델 불변식** | **[1]~[2] 모델 구성 오류를 잡는 층** — 모든 구조 과제 공통 어서션: ① 부호 포함 평형(Σ반력 벡터 = −Σ외력 벡터) ② 처짐 방향 부호(중력 재하 시 −Z) ③ 지지 DOF 개수·위치 ④ 교란 테스트(지지 하나 제거 시 반드시 실패해야 통과 — 어서션 자체의 살아있음 증명) | 전 항목 통과 |
| **V3 교차** | 동일 모델 Karamba vs PyNite (캡 내, 분할 포함 ≤20요소). **정식화 차이 통제**: 세장 부재 한정 또는 전단변형 설정 일치. M5에서 실행 | 변위 ≤ 1%, 부재력 ≤ 2% |
| **V4 판정** | **2단계 분리**: ① 좌굴 무관 부재 세트(짧은 인장재·세장 휨재)의 단면 체크만 자체 계산 vs Karamba Utilization 대조 ② 좌굴 포함 EC3 체크는 규준 조항·좌굴 곡선 명시 후 별도 허용치 설정 | ①활용률 차 ≤ 0.02 ②별도 정의 |

**실행 방식 — 어서션은 하네스 측** (자기 채점 금지): 현행 dev-wave 게이트(커밋 델타 +
실패진단)에는 수치 비교가 없음 → 과제별 기대값 스펙을 하네스에 주고, dev 전용 출력 조회
엔드포인트로 수치를 추출·비교하는 단계를 신설(M3; committed snapshot.json에는 출력 수치가
없음이 실측 확인됨 — 상세는 `archive/structural-analysis-dev-plan.md`). 테스트 대상 에이전트가
기대값 비교 코드를 스스로 작성하는 구조는 금지 — 거짓성공 반박 원칙과 정면 충돌.

**불합격 프로토콜**: V1 소스 불일치 = 출처 우선순위 + 2:1 다수결; V3 초과 = 해당 모델을
V2형 이론해 축소 모델로 분해해 귀책 엔진 판별; 공통 = 해당 층 불합격 동안 관련 기능
출력은 신뢰도 라벨 강등 또는 비활성.

## 실행 순서 (마일스톤)

- **M1**: `gh-karamba-cookbook.md` 작성 + Hello Karamba 라이브 검증.
  검증 항목: `#r` bare-name(`KarambaCommon.dll`) 해석 여부 실측, `FactoryLoad.LoadCaseCombination`
  실지원 범위, 스모크 = **Analyze + Utilization + OptiCroSec 3종 시그니처**.
- **M2**: 하이브리드 미니 씬 — **캡 예산 역산 설계** (예: 기둥 4×1요소 + 보 4×3분할 = 16 ≤ 20;
  처짐 어서션은 절점 위치 값으로 한정). 합격 기준: V2 문제 세트 + V2.5 공통 어서션 +
  `solved=true` 출력 어서션 + **GH_Model이 generic 소켓으로 네이티브 뷰 컴포넌트에 온전히
  전달되는지** 명시 확인.
- **M3**: `structural-analysis.md` + `structural_check.py`(판정 코드 실체) + 좌굴길이 정책 +
  하네스 측 수치 어서션 게이트 신설.
- **M4**: 라이브러리 Phase 1 + csproj `assets\data\**` Content + `data_read` 툴 + V1 통과.
- **M5 (이연)**: PyNite 브리지 + V3/V4 — 라이선스 걸림돌 시점에 착수.
